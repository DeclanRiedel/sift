# PostgreSQL native privilege matrix

Status: implemented and verified on Linux (ADR-148). Native Windows/macOS
acceptance remains deferred.

Add audited read-only `ReadPostgresPrivileges` and a typed HTTP/SDK report for one
selected public role (default current user), in the connected database. Include
current database, user schemas, ordinary/partitioned/foreign tables, views and
materialized views, individual live user columns, sequences and routines. Show
native per-privilege access and grant-option results, object OID/column number,
schema/relation identity and table RLS flags. Use PostgreSQL's has_*_privilege
functions, including PostgreSQL 17+ MAINTAIN only when supported. They account
for PUBLIC, effective inherited membership, ownership and superuser semantics;
do not reconstruct effective ACLs from explicit grants or perform SET ROLE.

The actor must already see the object through native ownership/privileges and
schema visibility. Never expand actor visibility using the selected role. Exclude
system/TEMP objects, secret catalogs, definitions and row data. Reject managed
schema-restricted profiles rather than selecting database-wide catalogs under a
narrow policy. Retain ordinary read-only and operation allow/block policy.
One supervised, parameterized native statement returns at most 201 objects with
bounded names/privilege vectors; cap response bytes and pages. Pagination is an
observation of a changing catalog, not a stable snapshot or completeness proof.

The report describes ACL checks, not executable-query authorization: schema
USAGE, RLS, security-definer behavior, policies, view options, HBA/login rules,
object dependencies and concurrent changes still matter. Role membership paths,
tablespaces/languages/types/large objects/configuration parameters,
and grant/revoke editors are separate work. Native ACL provenance is described in
[its subsequent plan](postgres-grant-provenance.md) (ADR-162). Excluded objects are not denial
results. No claim to enumerate every PostgreSQL privilege family.

Vim opens the selected role matrix from Roles with v, and closes with Escape.
Paging/refresh bind the exact instance/tenant/profile/session/query connection,
role, request UUID and generation; late responses cannot replace another source.
No native SQL is generated by the client. Native acceptance covers inherited and
non-inherited memberships, PUBLIC, grant options, column-only grants, RLS flags,
sequence/routine overload identity, native revocation, actor visibility and audit.
Run formatting, strict workspace/live-feature Clippy and the full workspace suite.
Windows/macOS native acceptance remains deferred.


## Acceptance evidence

PostgreSQL 17.10 HTTP/SDK acceptance passes in the existing disposable membership
fixture. The selected role has a quoted ampersand-bearing name, proving encoded
query dispatch. Native checks distinguish inherited versus SET-only membership,
PUBLIC grants, table versus column-only SELECT, owner ordinary SELECT revocation
with retained grant options, sequence USAGE and overloaded-routine EXECUTE/OIDs.
An actual SELECT under the subject returns no rows because of RLS despite the
column ACL result. The restricted connected actor cannot expand its visible
objects by selecting a stronger subject. Native revocation refreshes the result;
small pages have no duplicate or missing identities. Inspection preserves a
source SET ROLE context, and the audited operation has a successful terminal
record. The fixture reuses its restricted connection rather than retaining extra
native login pools beyond its configured connection ceiling.

GPUI acceptance opens the selected role through Vim v, pages through n, ignores
old request replies, refuses refresh on a changed query connection, and ignores
responses after Escape. All 1,734 workspace tests pass (five existing ignored),
with formatting and strict workspace/all-target and live-feature Clippy.
The report is scoped native ACL evidence, not a complete effective-access proof;
native ACL provenance is subsequently delivered in
[the provenance plan](postgres-grant-provenance.md) (ADR-162). Remaining privilege
families, membership/grant-chain paths and grant/revoke editors stay open.
