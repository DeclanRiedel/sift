Keyboard Sift configuration

sift.toml

One strict, portable desired-state file defines server policy and operator-managed resources. Edit it in Sift, save with :w, review the resource plan, import missing credential slots, and apply.

Secret bytes never belong here. UI preferences and keymaps are local; documents, rooms, approvals, sessions, results, and per-user credentials are live user state. Generated paths, resolved ports, and generations are destination-private. sift.lock is generated and read-only.

Rate and tenant limits

[server.rate_limits] has trusted_local_exempt and idle_ttl_secs. Each optional bucket— [server.rate_limits.control], [server.rate_limits.interactive], [server.rate_limits.query], [server.rate_limits.heavy_transfer], and [server.rate_limits.stream_bytes]—uses the same keys: refill_per_second, burst, and cost. Omitting a bucket disables that limiter.

[server.tenant_limits] has trusted_local_unlimited. Both [server.tenant_limits.defaults] and [server.tenant_limits.ceilings] accept optional connection_profiles, sessions, connections, concurrent_queries, cursors, and retained_result_bytes. Defaults apply to tenants; ceilings bound later tenant policy.

Unknown fields fail closed. Optional sections use safe defaults and may be omitted; hovering a key in the IDE shows its type and allowed values. Applying creates an immutable generation, and startup refuses unapplied drift.
