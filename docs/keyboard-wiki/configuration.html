sift.toml

One strict, portable desired-state file defines server policy and operator-managed resources. Edit it in Sift, save with :w, review the resource plan, import missing credential slots, and apply. Every key below lists its default or an example; keys marked required have no default.

Secret bytes never belong here. UI preferences and keymaps are local; documents, rooms, approvals, sessions, results, and per-user credentials are live user state. Generated paths, resolved ports, and generations are destination-private. sift.lock is generated and read-only.

Rate and tenant limits

[server.rate_limits] has trusted_local_exempt (default true) and idle_ttl_secs (default 600). Each optional bucket— [server.rate_limits.control], [server.rate_limits.interactive], [server.rate_limits.query], [server.rate_limits.heavy_transfer], and [server.rate_limits.stream_bytes]—uses the same keys: refill_per_second, burst, and cost. Bucket defaults, written as refill_per_second/burst: control 20/40, interactive 30/60, query 10/20, heavy_transfer 2/4, and stream_bytes 4194304/8388608; cost defaults to 1. Omitting a bucket disables that limiter.

[server.tenant_limits] has trusted_local_unlimited (default true). Both [server.tenant_limits.defaults] and [server.tenant_limits.ceilings] accept optional connection_profiles, sessions, connections, concurrent_queries, cursors, and retained_result_bytes. Both default to 100 connection profiles, 32 sessions, 64 connections, 16 concurrent queries, 64 cursors, and 268435456 retained result bytes; omitted keys are unlimited. Defaults apply to tenants; ceilings bound later tenant policy.

SQLite and Sift metadata

[server.drivers.sqlite] sets max_connections, the SQLite worker cap (default 8, range 1–128).

SQLite files belong to the server. Configure named directories under [server.drivers.sqlite.roots.<root-id>] with path, allowed_tenants (numeric tenant IDs; default empty, which denies every tenant), and read_only (default true). A SQLite connection uses [connections.sqlite] with root_id, a relative path, mode (read_only or read_write, default read_only), and optional busy_timeout_ms (default 1000, range 0–5000). Opening a connection requires an existing file.

For a local applied instance, choose View Sift Metadata (Read-only Snapshot) from the profile menu or command palette. Sift opens a separate inspection instance with a sift/metadata-inspection connection. It contains selected app metadata; credentials, tokens, SQL history and document contents are excluded. Return through the instance picker. Run the command again for a fresh snapshot.

Unknown fields fail closed. Optional sections use safe defaults and may be omitted; hovering a key in the IDE shows its type and allowed values. Applying creates an immutable generation, and startup refuses unapplied drift.

Desktop settings

UI preferences belong in your local settings.toml, separate from the server's sift.toml.

Dialogs have a draggable handle along their top edge. In Settings, Unpin modals controls this behavior and is on by default. To keep dialogs fixed, set:

ui.unpin_modals = false
Full operational details and threat boundaries are in docs/INSTANCE-CONFIG.md.
