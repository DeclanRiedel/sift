Shared rooms

One server, one room, several independent editors. Share SQL documents, presence, and query results without sharing a desktop or a password.

Everyone must connect to the same Sift instance and belong to the room's tenant. Two desktops running separate local instances do not become collaborators just because their room names match.

SSH logins on the same machine can also use different per-user Sift state roots. Verify the instance identity, not only the SSH hostname.

Get started

  1. Choose a shared instance using the hosting guide. HTTPS and SSH are transport choices; neither grants room access.
  2. Sign in and select the intended tenant. Have its administrator arrange tenant membership for your collaborators.
  3. Open the Collaboration panel, choose Rooms…, enter a name, and choose Create shared room.
  4. Select the room. Enter a collaborator's Member principal ID, choose Viewer, Editor, or Owner, and choose Add. Use the principal ID on this instance, not a GitHub username or email.
  5. For database execution, enter a saved Connection profile ID and choose Bind / unbind. An empty field unbinds the room.
  6. Collaborators can choose Join after an owner grants membership, then work on the same room-backed document.

Room administration shows members and retained shared results. Use Refresh to reload the room list. Selecting a room loads its details; it does not change the active room's People list.

Leave removes your membership; closing a tab or losing a socket is only a disconnect. A room must retain an owner. Treat Delete as a durable room action, not a way to disconnect.

Vim remains the editor interaction mode. : opens the command palette in normal mode; Esc cancels the current interaction. See the keyboard reference for execution commands.

Permissions intersect

Room roleRoom permission
ViewerObserve shared documents, presence, and available results; no document edits or query execution.
EditorEdit and execute when tenant permissions and connection policy also allow it.
OwnerAdminister the room and its membership; database restrictions still apply.

An operation needs permission from every applicable layer: tenant, room, and connection profile. Read-only rules and explicit denials are not overridden by room ownership. Join does not grant a role.

Removing tenant or room membership revokes live room access. Expired or revoked login sessions also end their sockets. Reconnecting cannot restore a removed grant; an authorized administrator must restore access.

Connections and shared results

A bound room uses a server-owned database connection. The database hostname is resolved from the Sift server, not each desktop. With SSH, forwarding reaches Sift; the remote Sift process still connects to the database from its own network.

Connection credentials stay behind the server's secret store. Room membership does not reveal them, and a room connection is not another member's personal transaction session.

Completed room runs publish immutable result references. Each reader pages independently: scrolling on one desktop does not advance another reader's cursor. Query results are not merged using the document CRDT.

Shared results are temporary, not an archive. The server retains up to 32 results per room, expires idle results after 10 minutes, and loses these process-local results on restart. Large results can spill to encrypted temporary files. Export anything you need to keep.

Editing and recovery

Only query text uses the CRDT. The server validates an update and commits it to metadata before acknowledging and broadcasting it. Presence, selections, database sessions, and results have separate lifecycles.

Reconnect reattaches and compares document version vectors to recover missing updates. A slow consumer may need a document resync instead of replay from the bounded event buffer. Sync payloads and incomplete transfers have size limits; they are not unbounded memory queues.

Presence uses a 30-second heartbeat lease. A disconnected peer can remain visible briefly until the socket closes or its lease expires. Server drain closes room sockets and releases their presence and live-writer leases.

Server-acknowledged text survives a server restart. Do not assume an unacknowledged local edit is durable just because it is visible in an editor; preserve your local buffer before resetting a failed replica.

Troubleshooting

SymptomCheck first
Cannot find or join a roomVerify instance identity, selected tenant, tenant membership, and the owner's room grant.
Can read but cannot edit or runCheck Viewer roles, the room binding, and connection read-only/operation policy.
Database host is unreachableCheck DNS, routing, and database permissions from the Sift server's machine.
Presence disappearsCheck heartbeat delivery, WebSocket proxy support, login expiry, and membership revocation.
Duplicate writer or replica conflictIndependent editors need distinct replica identities. Do not clone live replica state into two simultaneous writers.
