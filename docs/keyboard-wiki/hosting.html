Hosting Sift

Keep the desktop local while Sift and its database connections run elsewhere. Use HTTPS for a shared server or SSH for direct access to one remote machine.

Once connected, follow Shared rooms to grant membership, bind a database connection, and collaborate. Hosting a server alone does not grant access to its rooms.

Database credentials stay in the server's configured secret store. They never belong in sift.toml, URLs, shell arguments, or desktop presentation state.

Hosted HTTPS

Configure transport = "network", disable loopback bypass, select a durable metadata secret backend, and set public_base_url to the exact HTTPS origin. Keep Sift bound to loopback when the TLS proxy is on the same host. The proxy must forward both HTTP and WebSocket upgrades without rewriting /v1.

For a private Tailnet, Tailscale Serve provides the HTTPS boundary:

sudo tailscale set --operator=$USER
tailscale serve --bg http://127.0.0.1:7474
tailscale serve status

Wait for the HTTPS /v1/ready endpoint before connecting; first certificate issuance may take a moment. In Sift, use <leader> d c, choose a hosted server, and enter the HTTPS origin. Plain HTTP is accepted only for loopback.

Direct SSH

Open the server picker with <leader> d c, choose SSH, and enter a destination already understood by your system OpenSSH client, such as user@host or an SSH config alias. Sift preserves your host-key, agent, jump-host, and authentication policy.

The helper installs or reuses a compatible remote server, starts a private daemon, and forwards it to a local loopback port. Closing the desktop tunnel leaves durable remote state alive; reconnecting opens a fresh authenticated grant.

Recovery and identity

EventExpected behaviour
Network interruptionSift reconnects with bounded, jittered backoff.
Server restartThe instance stays the same; process-local sessions, connections, cursors, and sockets reopen.
Different instance idSift refuses the replacement. Forget and add it again only when the change is intentional.
Expired loginInteractive sessions refresh automatically and persist rotated credentials in the OS vault.

Operators can run the real two-device checks with test-tailnet-hosted.sh user@device or test-ssh-device.sh user@host. Both checks clean up only temporary state they created.
